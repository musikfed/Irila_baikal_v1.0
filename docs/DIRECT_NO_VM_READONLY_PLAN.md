# Прямая сборка PegiNelab OS без отдельной тестовой VM

**Заменяет неверную рекомендацию «сначала соберите обычную Ubuntu ext4 в Hyper-V».**

## Важное различие
Windows 11 Pro — пульт управления и программа записи на USB SSD, **не Linux-источник**. Для чтения Linux-ядра, подготовки initramfs и mksquashfs нужен Linux в одном из вариантов:

1. **Без установки ОС на ноутбук:** загрузить Ubuntu 24.04 Live-USB, взять его rootfs как Source, выполнить `prepare_source.sh` и `bake_image.sh`. Понадобится достаточно свободного места для промежуточной Linux-сборки и IMG на отдельном накопителе. На Live-USB данные из RAM могут исчезнуть при выключении, поэтому готовый IMG обязательно сохранить во внешнюю папку/диск.
2. **Из Windows без отдельного окна Hyper-V:** WSL2 с Ubuntu 24.04 (`wsl --install -d Ubuntu-24.04`). Это Linux-инструменты, запускаемые из Windows, но WSL2 использует технологию лёгкой виртуализации. У WSL могут быть ограничения loop/mount — их нужно проверять на конкретной установке. Системный раздел Windows не переразмечается; VHDX WSL занимает место на нём.
3. **Если уже существует рабочая Ubuntu/Debian на другом компьютере:** использовать её как исходный Linux Host. Не запускать скрипты Linux в Windows PowerShell без WSL.

**Отдельная виртуальная машина и тест QEMU не требуются для первого экспериментального запуска на физическом Acer.** Но отказ от тестирования увеличивает шанс получить незагружаемый SSD; первая загрузка через F12 — именно тест, не гарантия.

## Архитектура: Read-only как в ТЗ
`Ubuntu 24.04 Source` → `stage` → `mksquashfs` → `irina_baikal_1.0.img`.

Нативный компонент Ubuntu **casper** поддерживает `boot=casper`: ищет файл `/casper/filesystem.squashfs`, монтирует сжатую корневую систему Read-Only и создаёт рабочий OverlayFS. Никаких произвольных `root=/dev/sdb`: номера дисков меняются. Подробнее: https://manpages.ubuntu.com/manpages/noble/man7/casper.7.html .

Выходная GPT-разметка:
- ESP FAT32 UEFI с ядром, initramfs, загрузчиком;
- `IRINA_SYSTEM` ext4, содержащий **файл** `/casper/filesystem.squashfs` — не «сырое SquashFS-раздел»;
- `IRINA_DATA` ext4, отдельное постоянное хранилище для документов, почты и конфигурации; его интеграцию, автоматическое расширение и шифрование необходимо испытать отдельно.

**На первом этапе GRUB в EFI — временный проверочный путь.** Rust `bootx64.efi`, проверка ядра+initramfs+SquashFS и подпись Secure Boot — обязательные работы до заявления о защищённой версии. Один хеш ядра сам по себе защиту не гарантирует.

## Что пока не соответствует финальному ТЗ

- Полный пакет офисных программ, GIMP, Inkscape, Thunderbird, Linphone и Qwen 8B одновременно в сыром IMG **3–5 ГБ** практически не помещаются; одна Qwen 8B требует около 5 ГБ. Рекомендуется компактный корень + модель в DATA, а общий размер определять после замера SquashFS.
- Длительность записи зависит от размера IMG и реальной скорости USB 3.0, **«ровно две минуты» не гарантируются**.
- Hrag и Ollama должны быть встроены и протестированы отдельным этапом. Автоперехват HTTPS без согласия пользователя не устанавливаем: предлагается явный прокси / открытие URL через Hrag.
- Полный загрузочный образ **не создан в GitHub и не испытан на Acer**. Сборочные скрипты являются исходниками и требуют реальной сборки и исправлений по логам.

## Запись уже пустого внешнего USB M.2 SSD 256 ГБ

При наличии проверенного `.img` и `.sha256`, на Windows:
```powershell
Get-Disk | Select Number,FriendlyName,BusType,Size,IsBoot,IsSystem | Format-Table -AutoSize
```
Опознать внешний диск одновременно по **USB**, ёмкости 256 GB, модели, отсутствию признаков загрузочного/системного устройства и отключению/повторному подключению. Сравнить SHA-256 через `Get-FileHash`, затем записать IMG через Rufus (https://rufus.ie/). **Не форматировать заранее**: сырой IMG сам запишет GPT/ESP. **Никогда не выбирать внутренний диск с Windows**. После записи — F12 → USB SSD (при включённом UEFI Boot Menu).

**Первый запуск Acer — экспериментальный.** При ошибке загружаться обратно в Windows, а не форматировать внутренний SSD. До возможного отключения Secure Boot сохранить ключ восстановления BitLocker/шифрования устройства и понимать влияние на безопасность.
