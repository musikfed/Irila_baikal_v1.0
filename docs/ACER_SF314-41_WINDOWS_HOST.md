### Не устанавливать драйверы «наугад»

- **Не закладывать Intel Wi‑Fi:** на этом Acer показан **Qualcomm QCA61x4A**.
- Ubuntu 24.04 LTS: базовые компоненты `linux-image-generic`, `linux-firmware`, `mesa-vulkan-drivers`, `libgl1-mesa-dri`, `network-manager`, `pipewire`, `wireplumber`, `v4l-utils` по составу базового образа.
- Модули ядра, кандидаты: `amdgpu`, `ath10k_pci`, `snd_hda_intel`, `uvcvideo`. Не гарантировать загрузку каждого без проверки PCI/USB ID.
- Рутинное полное сканирование DMI/PCI при каждой сборке **не требуется**. Для диагностики при первом запуске достаточно `lspci -nnk`, `lsusb`, `dmesg` / `journalctl -k`, если какая-то функция не работает.

Из корня клонированного репозитория:


```powershell

```

Не запускать последний пример, если `requirements.txt` не создан.

## 3. Два разных SSD: главное правило безопасности

**HOST (НЕ ТРОГАТЬ)**: внутренний M.2 SSD Acer, заявленная ёмкость 512 ГБ, с Windows 11 Pro.

**TARGET (прошивка)**: отдельный **внешний M.2 SSD 256 ГБ**, подключён через USB 3.0 — целевой накопитель для `irina_baikal_1.0.img`. Эти диски **нельзя** выбирать только по буквам `C:`, `D:` или путям Linux `/dev/sdb`: номера меняются.

Проверка **только чтением** из PowerShell администратора:

```powershell
Get-Disk | Select-Object Number,FriendlyName,SerialNumber,BusType,Size,IsBoot,IsSystem | Format-Table -AutoSize
Get-Volume | Select-Object DriveLetter,FileSystemLabel,FileSystem,Size
```

Результаты с серийными номерами **не публиковать**. Проверить `BusType = USB`, ожидаемую ёмкость ~256 ГБ, название модели, отсутствие `IsBoot`/`IsSystem` и какой диск исчезает при безопасном отключении внешнего SSD. Эти признаки использовать **совместно**, никакой один не гарантирует безопасность.

Запись образа через Rufus (DD, если предложено) или иной проверенный способ **уничтожит все данные на выбранном внешнем SSD**. Не запускать запись, пока образ не собран и не проверен, а диск однозначно не опознан. **Разметка GPT/ESP будет внутри .img**, вручную заранее форматировать SSD не нужно. Нельзя передавать внутренний Windows-диск виртуальной машине как raw disk.

## 4. Архитектура разработки

- **Acer = пульт / Host**: Windows 11 Pro, установленный Python/uv, GitHub, тест UI и подготовка образа.
- **Build VM**: Ubuntu 24.04 LTS в Hyper-V или другой Linux VM на Windows (при наличии свободного места), Linux-инструменты для сборки SquashFS/GPT/initramfs и тестов в QEMU.
- **Target**: внешний SSD USB 3.0; собственный UEFI-запуск ОС «Ирина Байкал 1.0», при выборе в F12 без модификации внутреннего Windows-диска.
- **Функции Irina Shell**: бирюзово-зелёная тема, всплывающее меню, круглое превью HD WebCam/селфи, внешняя ВКС через Jitsi; собственная ВКС пока не реализована.
- **Безопасность**: для Rust-загрузчика нужны подписанный бинарник и проверка всей загрузочной цепочки (ядро, initramfs, SquashFS), не только хеша ядра.

**Текущий статус:** документ конфигурации не означает, что загрузочный IMG готов, что драйверы проверены на Linux, или что Windows-диск был затронут.
