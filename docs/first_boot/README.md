# Ирина Байкал 1.0 — первый аппаратный запуск

**29 октября 2026 года** · Acer Swift 3 SF314-41 · внешний M.2 USB SSD 256 ГБ · Windows 11 Pro на внутреннем NVMe сохранена.

**Источник доказательств:** ZIP с **18 фотографиями реального экрана**, снятыми владельцем после установки `irina_baikal_1.0_installed_secureboot.img`. Временные отметки снимков: 22:32–22:40 по имени файла. Это не скринкаст, не QEMU и не отрисованные макеты.

## Что реально работает

| Компонент | Наблюдение | Уверенность |
|---|---|---|
| Acer UEFI + Secure Boot | Подписанный shim/GRUB запустил Ubuntu на Acer | Подтверждено предшествующим испытанием и запуском установленной ОС |
| Ядро Linux | Загрузилось без прежней panic от Casper | Подтверждено экраном XFCE и `top` |
| Установленный ext4 | `df -h`: `/dev/sdb2` в `/`, размер **235 ГиБ**, свободно **232 ГиБ** | Подтверждено; авторасширение корня сработало |
| EFI | `/dev/sdb1`, около **511 МБ**, смонтирован в `/boot/efi` | Подтверждено |
| Графика | Xorg, xfwm4, меню XFCE, Thunar, фирменная тема «Ирина Байкал» | Подтверждено |
| Память | `top`: около **17,9 ГиБ RAM**, нагрузка невысока | Подтверждено состоянием на фото |
| Камера | Интерфейс показывает **Invalid constraint** | Требует диагностики разрешения/ограничений WebRTC; не доказывает поломку драйвера |
| Интернет | На снимке браузер не смог открыть сайт | Требует проверки Wi-Fi, DNS и доступа браузера |
| Почта и SIP | Окна просят установить Thunderbird и Linphone | Не были установлены в проверенном базовом профиле |

**Инженерное достижение:** от работающего CI-образа до реально запущенной на железе ОС с постоянным корнем ext4 и собственной графической оболочкой.

> Со слов автора, от идеи до этого этапа прошло около **пяти часов**. Отмечаем как историю первого прототипа, а не как показатель сроков полной разработки.

## 18 фотографий из переданного архива

Фото будут доступны прямо в GitHub в [галерее](index.md), после публикации исходного ZIP. Для каждого оригинала генератор создаст EXIF-free JPEG-превью с подписью и отметкой диагностических ограничений.

**Как закончить публикацию без Linux и без команд:**

1. На странице каталога `docs/first_boot` в GitHub нажать **Add file → Upload files**.
2. Перетащить переданный архив из Windows с названием **`photos-source.zip`** (не распаковывая) и сохранить commit.
3. GitHub Actions [Publish first-boot Acer gallery](../../.github/workflows/publish-first-boot-gallery.yml) создаст `index.md` и **18 фотографий в `docs/first_boot/photos/`**, убрав EXIF и уменьшив снимки для сайта.

**Публичность:** перед загрузкой архива обязательно убедитесь, что на фото нет паролей, токенов, приватных писем, серийных номеров, Wi-Fi SSID и других данных, которые нельзя публиковать. Данный архив содержит реальное окружение, а не нейтральные сгенерированные изображения. CI удаляет EXIF, **но не способен гарантировать удаление чувствительного текста, видимого на экране**.

## Фактические задачи после испытания

1. Установить приложения: LibreOffice (Writer, Calc, Impress), Thunderbird, GIMP, Inkscape, Linphone; проверить, что ссылки оболочки действительно их запускают. Для `core` уже есть retry-автоматизация после Wi-Fi; она не была подтверждена фотографиями.
2. Диагностировать WebRTC: `Invalid constraint` в настройках камеры — проверить тип/размер видео, разрешения и безопасный origin.
3. Сеть: проверить NetworkManager, Wi-Fi QCA61x4A, DNS и браузер, не путать отсутствие интернета с отсутствием драйвера.
4. Звук: оригинальное байкальское интро после входа в графический сеанс. Подписанная UEFI-цепочка и Windows BitLocker не изменяются.
5. Разработать отдельный Windows↔Linux пакетный мост; Windows без WSL/специального драйвера **не устанавливает `.deb` напрямую на ext4**. Не использовать EFI-раздел как склад программ.
6. В будущем снимать нативные PNG вместо фотографии монитора: можно будет сделать более чёткую галерею без муара.

## Не менять успешный USB-диск без необходимости

**Работающий `irina_baikal_1.0_installed_secureboot.img` и текущий USB SSD сохраняются.** Новые идеи разрабатываются отдельно. `Rufus START` заново стирает внешний SSD — это не механизм безопасного обновления установленной системы.
