# Если WSL не запускается — «Ирина Байкал»

Это руководство для Acer на Windows 11 Pro с Ubuntu-24.04 в WSL2, существующими Linux-проектами на D: и рабочей папкой `F:\irinabaikal`. Внешний USB SSD 256 ГБ отображается как отдельный неразмеченный диск ~238,46 ГиБ — **не обращаться к нему во время восстановления WSL**.

## Прежде всего

Нельзя делать `wsl --unregister`, `wsl --install` поверх существующей Ubuntu, удалять `ext4.vhdx`, форматировать D:/F:, выполнять `diskpart clean`, `wsl --import-in-place` или `wsl --set-version` наугад. В текущем Ubuntu есть личные проекты; `wsl --export` копирует **все** файлы, включая секреты и ключи, если они там есть. Не отправляйте в GitHub архив экспорта и конфиденциальные файлы.

**Если прежний PowerShell-скрипт всё ещё выполняет экспорт/импорт, не прерывайте его.** `wsl --shutdown` завершает все WSL-сеансы: кратковременное прекращение работы ожидаемо, но после завершения `wsl --list --verbose` должен показать зарегистрированные дистрибутивы. Приглашение `COPY-IRINA` — это ещё НЕ созданный `IrinaBuilder`.

## Диагностика без изменения данных

В **новом PowerShell** выполните:

~~~powershell
wsl --list --verbose
wsl --status
wsl --version
Test-Path "F:\irinabaikal\WSL-IrinaBuilder"
Test-Path "F:\irinabaikal\Ubuntu-24.04-export.tar"
~~~

Либо скачайте [Diagnose-IrinaWSL.ps1](../windows/Diagnose-IrinaWSL.ps1) и запустите его — он не останавливает, не импортирует и не удаляет WSL.

Если вывод показывает `Ubuntu-24.04`, но не `IrinaBuilder`, это означает, что **новая сборочная копия не зарегистрирована**. Можно проверить старую Ubuntu так:

~~~powershell
wsl --distribution Ubuntu-24.04 --user root --exec /bin/true
~~~

Если код завершения 0, Ubuntu запускается. Для обычного интерактивного входа:

~~~powershell
wsl --distribution Ubuntu-24.04
~~~

Если зарегистрирована `IrinaBuilder`, проверяйте и её через `wsl -d IrinaBuilder -u root --exec /bin/true`.

Если вы видите **WSL_E_DISTRO_NOT_FOUND**, убедитесь, что название точно совпадает с `wsl -l -v`. Если имя существует, но стартует с иной ошибкой, сохраните **точный текст ошибки и код**. Не запускайте автоматический ремонт без диагностики.

Если **все** дистрибутивы не запускаются, сначала закройте PowerShell после завершения экспорта/импорта, затем проверьте службу через `Get-Service WslService,LxssManager -ErrorAction SilentlyContinue`. Вы можете открыть официальный [WSL Troubleshooting от Microsoft](https://learn.microsoft.com/en-us/windows/wsl/troubleshooting) и проверять проблему по конкретному коду. Не переустанавливайте WSL «на всякий случай».

## Особенности D: и F:

- D: — уже существующая работающая Ubuntu WSL и проекты; при диагностике **ничего на D: не удалять**.
- F: — большой раздел NTFS на внутреннем 512 ГБ NVMe, подходит для хранения образа `F:\irinabaikal\irina_baikal_1.0.img`, а также независимого `ext4.vhdx` сборочной WSL.
- Внешний 256 ГБ SSD — неразмеченный диск, **НЕ F:**. Цель будущей записи Rufus, но до завершения сборки его не трогаем.
- `wsl --export Ubuntu-24.04 ...` сделает полный архив существующей Linux-системы, включая чужие проекты и возможные закрытые материалы; **если нужна только сборка ОС, предпочтительнее чистая отдельная Ubuntu-среда**, а не экспорт ценных рабочих каталогов.

Для продолжения сборки после восстановления см. [BUILD_WSL_F_DRIVE.md](BUILD_WSL_F_DRIVE.md).

**Отдельно:** ошибки подключения к localhost-прокси в WSL могут затронуть интернет внутри Linux, но сами по себе не доказывают поломку файловой системы. Понадобится точная ошибка запуска `wsl -d Ubuntu-24.04`.
