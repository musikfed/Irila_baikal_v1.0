# Windows → Ирина Байкал: пакетный мост без Linux-терминала

## Зачем

Владелец хочет заранее, **из графической Windows**, подготовить программы, зависимости и обновления драйверов к уже загрузившейся «Ирине Байкал» на внешнем M.2 SSD. После следующего выбора USB SSD через F12 система должна сама установить подготовленное и показать результат в графике.

**Проектируем безопасный пакетный мост; не выдаём его за уже работающий функционал на текущем R1.**

## Что подтверждено на реальном Acer

- Установленная «Ирина Байкал 1.0» реально запускается с Secure Boot на внешнем Realtek RTL9210B-CG.
- `df -h` уже показал `/dev/sdb2` размером **235 ГиБ**, поэтому Linux автоматически расширил root ext4, EFI-раздел 511 МБ.
- Драйверы `amdgpu`, `ath10k_pci`, `snd_hda_intel`, `uvcvideo`, USB UAS и XHCI уже были включены в базовую сборку/ядро как известные кандидаты. Linux **сам обнаруживает устройства и загружает нужные модули при каждом старте**; это нормальная и быстрая автоматическая работа ядра, а не ручная «инициализация железа» пользователем.

## Почему R1 нельзя безопасно «заполнить программами» из Windows как обычную папку

Текущий диск имеет GPT раздел 1 (EFI FAT32 512 МБ) и раздел 2 (`IRINA_ROOT` ext4 почти на весь SSD). Windows 11 **штатно не монтирует ext4 для записи**, а EFI-раздел предназначен для загрузчика и должен оставаться нетронутым. Копирование дерева `/usr` без `dpkg` не выполняет зависимостей, триггеров, учёт прав Unix, обновления базы пакетов и конфигурации служб.

Даже официальный Microsoft `wsl --mount` для физического диска **требует администратора, установленную WSL и отключение устройства от Windows**. Для этого ноутбука WSL ранее была удалена, а цель проекта — **обойтись без неё и без Linux CLI на Windows**. Мы **не будем** применять сторонний ext4-драйвер, вмешиваться в UEFI/Windows ESP или рисковать работающим SSD.

Документация Microsoft: https://learn.microsoft.com/en-us/windows/wsl/wsl2-mount-disk

## Что работает уже сейчас без запуска Ирины

**Путь A — «Все программы внутри готового IMG» (существующий CI):** GitHub Actions `Build Irina Baikal Installed USB Secure Boot`, `profile=full`, `max_mib=12288`. GitHub скачивает пакеты Ubuntu и разрешает зависимости **при сборке**, формирует готовый ext4 с `dpkg`. После Windows получает завершённый IMG — никакой установки внутри ОС до первого входа. **Важно:** заново записать этот IMG Rufus означает **полностью стереть текущую установленную систему на USB**. Это только вариант для нового SSD/с резервной копией и не выполняется автоматически. Полный профиль требует отдельной CI-проверки на пакеты.

**Путь B — «Поставить программы после подключения сети» (имеется в R1):** `irina-auto-provision.timer` повторяет `apt-get` после Wi-Fi, показывает статус в XFCE. Требует загрузки Ирины и работающего интернета, и фотографии пока не подтверждают завершение установки.

## Проект R2 — USB с безопасным обменом данными

Новый, отдельный образ, **не поверх проверенного R1**, будет иметь:

```text
GPT (на одном внешнем USB SSD)
  #1  512 MiB FAT32  IRINA_EFI       Secure Boot shim/GRUB/kernel — никогда не склад пакетов
  #2  2–4 GiB exFAT IRINA_EXCHANGE  Доступен для чтения/записи из Windows
  #3  ext4 IRINA_ROOT                Постоянный Linux, авторасширение до остатка SSD
```

Алгоритм:

1. **Windows GUI** выбирает приложения из проверенного списка, получает/проверяет Linux-пакеты для Ubuntu 24.04 amd64 и пишет **только обычные файлы** в `IRINA_EXCHANGE/inbox`, не трогает GPT, EFI, ext4 и Windows-диски.
2. Источник пакетов — официальный Ubuntu APT с подписанными `Release/InRelease` и хешами `Packages`, или пакетный офлайн-набор, подготовленный Ubuntu GitHub Actions. Нельзя исполнять случайный `.exe`, `.sh`, `.deb` или `postinst` из неизвестного ZIP по щелчку.
3. После F12 служба Linux монтирует `IRINA_EXCHANGE` с `nodev,nosuid,noexec`, **проверяет манифест, версии, архитектуру, контрольные суммы и доверие репозиторию**, устанавливает через `apt`/локальный репозиторий с `dpkg`. Статус/ошибки выводятся в графическом Irina Setup. При сбое не ломает загрузчик; повтор возможен.
4. Проверять цепочку загрузки, сетевые и мультимедийные драйверы как обычно. Не запускать пользовательские скрипты из папки Windows под root. Личные ключи, пароли Wi-Fi и лицензии в обменную папку не помещать.
5. Автоматическое расширение **только раздела 3** с `IRINA_ROOT`, строгая проверка GPT/USB/model/размера/маркировки — прежняя R1-служба проверяет раздел 2 и не может использоваться без модификации.

**R2 ещё не собран и не испытан.** Пока существующий R1 работает, не форматировать его, не делить на новые разделы в Windows и не заменять проверенный IMG без резервной копии.

## Установка приложений: главное архитектурное различие

**Распаковка файлов — лишь часть установки Linux-пакета.** Надёжная установка требует проверки подписей/хешей, разрешения зависимостей и версий, обновления `/var/lib/dpkg`, выполнения жизненного цикла пакетов и установки иконок/десктопных файлов. Это автоматизируется не BIOS и не терминалом владельца, а **проверенным Linux-пакетным движком в образе или после загрузки**.

**Модель «Windows готовит → Linux применяет» сохраняет удобство Windows и целостность Ubuntu.**
